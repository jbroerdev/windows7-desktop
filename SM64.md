# Super Mario 64 – EU / Deutsch

Eigenes Desktop-Fenster unter `/sm64` oder `/mario`; Startmenü → Spiele → Super Mario 64. Über das Kontextmenü im Startmenü können eine Desktop-Verknüpfung und Taskleisten-Anheftung erstellt werden.

Der Webport basiert auf [sm64ex](https://github.com/sm64pc/sm64ex), einem auf der n64decomp-Decompilation aufbauenden Port. Der Browser führt WebAssembly/WebGL aus. Ein separater Docker-Dienst liefert ausschließlich die kompilierten Dateien über das authentifizierte Desktop-Gateway. Der Dienst veröffentlicht keine Host-Ports. Share-Benutzer haben keinen Zugriff.

## Privater Bau

Die EU-ROM muss SHA1 `4ac5721683d0e0b6bbb561b58a71740845dceea9` haben. ROM und kompilierte Spieldaten sind ausdrücklich von Git und dem allgemeinen Desktop-Docker-Kontext ausgeschlossen. Sie dürfen nicht ins öffentliche Quellcode-Repository hochgeladen werden.

Mit installiertem Docker und Node:

```
node scripts/build-sm64.mjs "/pfad/zur/baserom.eu.z64"
docker compose -f compose.yaml -f compose.sm64.yaml up -d --build
```

Weitere bereits verwendete Compose-Module müssen beim Deployment ebenfalls angegeben werden. Der Bau benötigt mehrere GB freien Speicher. Die Dateien werden in `services/sm64/build/` abgelegt. Alternativ `SM64_BUILD_DIR` auf ein vorhandenes privates Build-Verzeichnis setzen. Der Pin des Quellarchivs und die ROM-Prüfsumme werden beim Bau verifiziert. Der historische Webport wird mit Emscripten 2.0.34 gebaut; die Integrationspatches ersetzen die gemeinsame Browser-Speicherung, setzen die EU-Sprache auf Deutsch und ermöglichen Pause.

## Spielstände und Steuerung

WASD: Bewegung; L: Sprung; Komma: Angriff; K: Ducken; Leertaste: Start/Pause; Pfeile: Kamera. SDL unterstützt Gamepads. Physische Controller müssen separat mit dem jeweiligen Browser getestet werden.

Die vier originalen Speicherplätze werden als 512-Byte-EEPROM pro Desktop-Benutzer serverseitig in `<DATA_DIR>/sm64/<Hash der Benutzer-ID>.json` atomar gespeichert. Der Browser verwendet dafür keinen gemeinsamen localStorage. Ein erneutes Öffnen lädt den zuletzt vom Spiel gespeicherten Fortschritt. Dies ist kein Emulator-Schnellspeicher für einen beliebigen Zeitpunkt. Benutzerwechsel und Share-Modus dürfen keine Spielstände anderer Benutzer überschreiben. Beim Minimieren oder Fokusverlust pausiert das Spiel; Fortsetzen erfolgt über die Werkzeugleiste. Eine Sperren-Wiederherstellung öffnet das Startfenster erneut; laufender RAM-Zustand wird nicht serialisiert.

Prüfung: `node --test sm64-gateway.test.mjs`; zusätzlich echter Docker-Bau und Browser-Spieltest erforderlich.
